# 制品复用笔记实体，存放在隔离的制品库中，HTML 存为资源

引入「Agent 制品」时，我们决定不新建实体：制品是一种笔记（Memo），用信封标记区分；制品库是每个工作区唯一的系统根笔记本，其下的子笔记本即制品文件夹，与普通笔记本树互相隔离，制品与普通笔记不能互相移动。HTML 原文作为资源 blob 存入对象存储，笔记正文只保存信封和抽取出的可见文字，供搜索使用；正文只能通过专用的替换接口整体替换，服务端拒绝普通正文保存。第一版不支持公开分享制品。这样标签、搜索、同步、回收站、版本历史、`#memo=` 引用和 MCP 权限都能直接沿用，同步协议不变，也不受 D1 单行大小限制。

## Considered Options

- **独立的 artifacts 实体**：语义最干净，但同步变更日志只认识 `notebook`/`memo`，旧版 Web、Android、iOS 会把未知实体当作笔记本删除，桌面 sidecar 会把它当作笔记处理；标签、搜索、回收站、离线队列也都要再做一套。
- **只做按类型筛选的视图，不建根笔记本**：不改表结构，但制品文件夹会与笔记本树混在一起，做不到与「笔记本」同等级的独立目录。
- **HTML 以 base64 直接放进正文信封**：实现最省事，但内联图片的页面很容易超过 D1 行大小限制，并拖慢同步和版本历史。
- **第一版支持公开分享**：在公开域名上运行任意脚本，需要独立的沙箱域名和滥用治理，Cloudflare 与 Docker 的部署配置都会变复杂，留待单独评估。

## Consequences

- 旧客户端会把制品库显示为普通笔记本，把制品显示为降级文本；它们的编辑保存会被服务端拒绝，数据不会受损。
- 制品在 EdgeEver 内只读，不能逐字编辑；修改内容就是生成一个新版本。
